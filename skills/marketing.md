You are writing a Case Study Club BD marketing/retrospective post (weekly journey post, LinkedIn + Facebook group). This is NOT a personal essay about feelings toward AI or UX philosophy in the abstract. It is a concrete activity report with reflection layered on top. Mentor feedback on a rejected draft made this distinction explicit: a philosophical post without named course-steps reads as generic, even if well-written.

## Non-negotiable rules (apply to every post, every time)

- Zero em dashes. Ever. Use commas, periods, or restructure the sentence.
- Natural spoken Bangla, not translated-English boilerplate. Match the student's own voice, not a corporate tone.
- If a reference/sample post is shown as a style example, take the STRUCTURE, never copy actual lines or exact phrasing. Lifting someone else's specific sentences and lightly rewording them is plagiarism, not inspiration, even if the words change.
- Verify any quote or statistic before using it (WebSearch), never present an unverified claim as fact.

## Required structure (checklist, confirm every row before calling a draft done)

1. **আগে যা ভাবতাম** — a specific, concrete misconception (not vague), e.g. "Case Study মানে সুন্দর UI mockup আর Design System দেখানো"
2. **এই সপ্তাহে যা করলাম** — a NAMED, SPECIFIC list of the actual UX process steps covered that week, pulled from the vocabulary list below. This is the single most commonly missed requirement. Do not summarize it as "research" in the abstract; name the actual stages.
3. **একটা concrete mentor-feedback anecdote** — a specific moment where a mentor or team corrected/improved the student's actual submitted work (e.g. interview questions getting revised), not a general statement that mentors are helpful. This is the "most surprised/most learned" beat, and it should be a real, specific incident, not invented.
4. **Checklist of learnings** (3-5 bullets, ✅ marker) — grounded in the actual named process steps above, not generic UX platitudes
5. **Collaboration/community point** — grounded in a specific interaction (mentor feedback + team discussion), not an abstract "coworker not competitor" claim floating alone
6. **Forward-looking line naming the ACTUAL next course modules** (ask the student what's next if not already told; common ones: Ideation, MVP, Wireframe, UI Design, Prototype) — in addition to, not instead of, the student's own project's next step
7. **Full thank-you list** — every mentor by name the student has mentioned (check for more than one; Case Study Club BD typically has multiple named mentors, not just one), plus "সকল Mentor, Support Mentor এবং পুরো Case Study Club BD টিম"
8. **Closing line** — short, warm, matches brand tone (green heart emoji is on-brand)
9. **Hashtags** — must include `#CaseStudyClubBD` (with BD), not just `#CaseStudyClub`

## UX vocabulary reference — draw from this, do not invent generic substitutes

Use these as the actual named activities/stages when describing "what we did this week." Pick only the ones genuinely done; do not pad the list.

**Research phase:** Design System Explanation, Project Scoping, Research Planning, Secondary Research, Competitor/Competitive Analysis, Survey Question (design), Interview Question (design), Field Research, User Interview, Primary Research

**Synthesis phase:** Affinity Diagram, Persona, Journey Map, Problem Statement, Pain Point identification, Insight synthesis

**Ideation/build phase (usually comes later in the course, only reference if actually reached):** Ideation, MVP (Minimum Viable Product), Wireframe, UI Design, Design Tokens, Prototype, Usability Testing

## Content type by purpose (mentor's Social Media Content Strategy rule)

Before writing, decide which of these 4 types the post is, and write accordingly. This is not just "how to write a post," it's content strategy — different purpose needs different length/depth.

1. **Personal achievement / personal opinion** — সহজ ভাষা, ছোট লেখা, অনুভূতিটা সরাসরি বলা, অপ্রয়োজনীয় বড় শব্দ/ব্যাখ্যা নেই। এক-দুই লাইনের একটা সরল স্টেটমেন্টই যথেষ্ট, তারপর থামা। উদাহরণ: "একটা ভালো Product যেমন একজন মানুষ একা তৈরি করতে পারে না, তেমনি একটা অর্জনও একজনের একার হয় না।" — এর পরে অযথা বড় ব্যাখ্যা যোগ করা হবে না।
2. **Learning post** — শুধু Topic বলা, সহজ করে explain করা, লম্বা essay না লেখা।
3. **Criticism / Analysis** — এখানে reference থাকবে, উদাহরণ থাকবে, একটু বিস্তারিত/broad হবে — এই একটা type-ই বড় করে লেখার অনুমতি পায়।
4. **General social media rule (সব type-এর উপরে প্রযোজ্য)** — মানুষ পড়তে না, স্ক্যান করতে আসে। তাই: ছোট paragraph, বেশি white space, ৮-১২ লাইনের মধ্যে মূল কথা শেষ, storytelling থাকলে ভালো।

**Achievement/celebration post-এর জন্য practical টেমপ্লেট** (personal-opinion rule অনুযায়ী, ছোট রাখা):
- ১ লাইনের একটা সরল উপলব্ধি/স্টেটমেন্ট (heart emoji দিয়ে শেষ করা যায়)
- ১-২ লাইনে কী অর্জন হলো
- টিমমেট/মেন্টরদের নাম ধরে ছোট thank-you (প্রত্যেকের জন্য এক লাইনের বেশি না)
- প্রজেক্টের লক্ষ্য এক লাইনে (থাকলে)
- ছোট closing লাইন + emoji

## Before finalizing, ask the student

- "এই সপ্তাহে ঠিক কোন কোন step আসলে করা হয়েছে ক্লাসে?" (which of the above were actually covered — do not guess)
- "কোন mentor-feedback moment-টা সবচেয়ে মনে আছে?" (get the real anecdote, do not invent one)
- "সবগুলো mentor-এর নাম কী কী?" (do not assume only one mentor)
- "সামনের সপ্তাহে কী নিয়ে কাজ হবে বলে জানানো হয়েছে?" (next modules, from the actual course schedule if known)
